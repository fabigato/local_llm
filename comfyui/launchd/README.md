# Running ComfyUI headless (launchd daemon)

ComfyUI itself is **not** part of this repo — it's installed on the host at
`~/ComfyUI-Installs/ComfyUI`. What lives here is the host config that makes it
start **at boot, with nobody logged in**, so openclaw and the Tailnet URL keep
working after an unattended reboot.

## Why a LaunchDaemon and not a LaunchAgent

ComfyUI used to be served by **Comfy Desktop.app**, registered as a *Login Item*.
Login Items — and LaunchAgents — only load when a GUI user logs in. After a reboot
with nobody at the desk, ComfyUI was simply down and every consumer got connection
refused.

A **LaunchDaemon** (`/Library/LaunchDaemons`) loads at boot, before and independent
of any login. This works here only because **FileVault is off**; with FileVault on,
the boot volume stays locked until someone authenticates at the login window and no
daemon runs before that.

## Files

| File | Purpose |
| --- | --- |
| [com.local.comfyui.plist](com.local.comfyui.plist) | The daemon definition. Canonical copy — edit here, then reinstall. |
| [comfyui-daemon.model-paths.yaml](comfyui-daemon.model-paths.yaml) | `--extra-model-paths-config` for the daemon: maps every model type to `~/ComfyUI-Shared/models`. |

### Why the model-paths file is duplicated here

Comfy Desktop generates its own copy at
`~/Library/Application Support/Comfy Desktop/instance-model-paths/<instance-id>.yaml`,
stamped *"Generated by Comfy Desktop — do not edit manually."* Pointing the daemon at
that file would make a boot-critical service depend on a path Desktop rewrites at will.
So the daemon reads its own copy instead.

The cost is drift: if you change shared model directories in Desktop, re-sync it.

```sh
cp "$HOME/Library/Application Support/Comfy Desktop/instance-model-paths/inst-1783020951345.yaml" \
   comfyui/launchd/comfyui-daemon.model-paths.yaml
```

## Install

The plist is **copied**, never symlinked. launchd refuses to load a root daemon whose
plist is writable by a non-root user, and a symlink into a repo in `$HOME` is exactly
that — a user-writable file describing a root-launched process, which is a privilege
escalation. Root owns the installed copy; this repo holds the reviewable source.

```sh
# 1. Free port 8188 if Comfy Desktop is serving it
osascript -e 'quit app "Comfy Desktop"'

# 2. Install as root:wheel 0644 and start
sudo install -o root -g wheel -m 644 \
  comfyui/launchd/com.local.comfyui.plist \
  /Library/LaunchDaemons/com.local.comfyui.plist
sudo launchctl bootstrap system /Library/LaunchDaemons/com.local.comfyui.plist

# 3. Come back up after a power cut, too
sudo pmset -a autorestart 1
```

## Operating it

```sh
# Status (PID, last exit code and reason)
sudo launchctl print system/com.local.comfyui

# Stop / start — needed before using Comfy Desktop's own managed instance
sudo launchctl bootout system/com.local.comfyui
sudo launchctl bootstrap system /Library/LaunchDaemons/com.local.comfyui.plist

# Logs
tail -f ~/ComfyUI-Installs/comfyui-daemon.log
tail -f ~/ComfyUI-Installs/comfyui-daemon.err

# Health + which device it grabbed (want "mps", not "cpu")
curl -s 127.0.0.1:8188/system_stats | python3 -m json.tool
```

## Choices baked into the plist

- **`UserName fabigato`** — starts at boot without a session, but runs as the login
  user so generated images in `~/ComfyUI-Shared/output` aren't root-owned.
- **`--listen 127.0.0.1 --port 8188`** — stated explicitly rather than relying on
  defaults. Loopback-only is load-bearing: see the README's "Exposing ComfyUI
  remotely" section for why `0.0.0.0` and `100.x` both break consumers.
- **`HOME=/Users/fabigato`** — launchd daemons inherit no `HOME`. Without it,
  ComfyUI-Manager and the HuggingFace cache resolve paths wrongly.
- **`ProcessType Interactive`** — exempts the job from the background CPU/IO
  throttling launchd applies to `Standard`. It serves interactive requests.
- **`KeepAlive` + `ThrottleInterval 10`** — also what makes ComfyUI-Manager's
  "Restart" button work: Manager exits the process, launchd returns it ~10s later.
- **Dropped `--feature-flag show_signin_button=true`** from Desktop's argv; it's a
  Desktop-only UI flag. Kept `--enable-manager --disable-smart-memory`.

## Consequence: Comfy Desktop is now a maintenance tool, not the server

Desktop **cannot attach to an externally started backend**. Its managed instance always
spawns its own server, and with `"portConflict": "auto"` it will either move to 8189
(a second process loading models into the same unified memory, while openclaw and the
Tailnet URL still talk to 8188) or offer to kill the daemon — which `KeepAlive` then
restarts, causing a fight.

Two consequences:

1. **For daily use**, point Desktop at the daemon with a **Remote Connection** instance
   (`File ▸ New Instance ▸ Remote Connection`, URL `http://127.0.0.1:8188`), or just
   use a browser. In remote mode Desktop suppresses its update/snapshot/rollback/pip
   panels, so it's an Electron window around the same web UI — no capability gain.
2. **For version changes**, stop the daemon first and launch Desktop's *local* instance.

## Updates, now that Desktop no longer launches ComfyUI

`autoUpdateComfyUI` never fires if Desktop isn't launching the instance, so the version
is **pinned until you act** — currently a detached HEAD at tag `v0.31.1`.

ComfyUI-Manager is a pip package in the venv (`comfyui-manager 4.2.2`) and is enabled by
`--enable-manager`, so it and its `cm-cli` are server-side and unaffected by the move.

- **Custom nodes** — Manager in the browser, or:
  ```sh
  export COMFYUI_PATH=~/ComfyUI-Installs/ComfyUI/ComfyUI
  $COMFYUI_PATH/.venv/bin/cm-cli save-snapshot   # always snapshot first
  $COMFYUI_PATH/.venv/bin/cm-cli update all
  ```
- **ComfyUI core version bumps** — prefer Desktop with the daemon stopped. The env is a
  pinned Comfy bundle (`comfy-bundle:mac-mps:v0.20.1-env1`, torch 2.10.0, Python
  3.13.12) and Desktop tracks `lastVerifiedTorchStack`. A plain `pip install -r
  requirements.txt` after a Manager update can pull a torch wheel that quietly breaks
  MPS; Desktop also writes snapshots and `backup_branch_*` rollback branches.

## Known-unverified

Whether Metal/MPS works with **no window-server session at all** was not settled at
setup time — the daemon was confirmed on `mps` while a user was logged in, which does
not prove the headless case. Test by logging out (not rebooting) and loading the Tailnet
URL from another device. If it falls back to `cpu` or fails, the fallback plan is
automatic login plus an agent that immediately locks the screen — a real GUI session,
screen locked.
